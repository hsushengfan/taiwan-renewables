# 網站第一版：已確認的方向

> 這份文件記錄已經決定的事。還沒決定的列在最後。

## 定位

- **給誰看**：能源相關業者。
- **回答的問題**：目前的發電狀況，以及各機組的歷史發電狀況。
- **核心指標**：發電量、容量因數、機組狀態（即時與歷史）。
- **不顯示 availability**：台電的資料沒有「實際可用容量」，真正的 availability 算不出來。
  用備註推估的數字會把「風小」和「設備不能用」混在一起，對業界使用者容易誤導。
  網站改用兩個資料裡確實有的事實：容量因數（發電量 ÷ 裝置容量）和台電標註的狀態。
- **設計參考**：以 [Open Electricity](https://openelectricity.org.au)（澳洲，前身是 OpenNEM）為基礎。

## 功能

- **時間長度自己選**：24 小時、7 天、30 天、1 年、自訂。
- **篩選組合**：單看某個能源類型（例如太陽能）、單看離岸風電、單看某一個機組。
- **資料更新頻率**：每 10 分鐘（和台電的更新頻率一樣）。

## 頁面

| 頁面 | 內容 |
|---|---|
| **總覽** | 目前總發電量與各能源佔比、過去 24 小時的堆疊面積圖 |
| **能源類型頁**（例如離岸風電） | 該類型的發電量曲線、容量因數、機組表格 |
| **機組頁**（例如沃一風） | 發電量對裝置容量的曲線、狀態時間軸、容量因數的歷史 |

## 視覺化

- **堆疊面積圖**當首頁主角：同時看到佔比和隨時間的變化。圓餅圖或數字卡片當輔助。
- **狀態時間軸**：機組頁用一條橫向色帶顯示每個時段的狀態（正常、檢修、故障、主動少發）。
  這是本站資料獨有的價值：看得到發電量下降的原因。
- **可排序的機組表格**：容量、目前發電量、容量因數，加一條小趨勢線和狀態色帶。
- 長時間範圍改用彙總資料，避免一次畫幾萬個點：
  24 小時～7 天用每 10 分鐘的資料；30 天以上用每小時或每日的彙總。

## 能源分類（11 類）

燃煤、民營燃煤、燃氣、民營燃氣、其它火力（燃料油、汽電共生）、儲能、水力、
其它再生能源、太陽能、陸域風電、離岸風電。

民營電廠獨立成自己的類別。同一個家族用同一個顏色，第二個成員加斜線紋路
（民營燃煤、民營燃氣、陸域風電），避免顏色超過 8 種而難以分辨。

## 離岸風電的分類

台電的資料只有「風力」一類，沒有區分陸域和離岸，所以要自己在機組表標記。

**離岸**：離岸一期、離岸二期、海洋竹南、海能風、沃一風、沃二風、沃四風、沃南風、
芳一風、芳二風、允湖、允西、中能風、龍A風、龍B風、龍三風。

**陸域**：其餘的風力機組（包含彰品風）。

## 網站的程式

網站是靜態網站（只有 HTML、CSS、JavaScript，沒有額外的伺服器），放在 `site/` 資料夾，
用 GitHub Pages 發布。`site/` 有修改並合併進 main 時，會自動重新發布（`.github/workflows/pages.yml`）。

| 檔案 | 用途 |
|---|---|
| `site/index.html` | 頁面的骨架 |
| `site/css/style.css` | 外觀（顏色、排版；淺色和深色模式） |
| `site/js/config.js` | Supabase 的網址和公開金鑰、多久更新一次 |
| `site/js/api.js` | 向 Supabase 讀資料（只呼叫 `api_` 函式） |
| `site/js/i18n.js` | 介面文字的中英文對照 |
| `site/js/app.js` | 主程式：讀資料、算數字、畫圖表和表格 |

目前完成的是**總覽頁**：四個重點數字、堆疊面積圖、能源類型表、機組表，
可切換 24 小時／7 天、中文／英文，每 3 分鐘自動更新。

還沒做：30 天與 1 年的範圍、能源類型頁、機組頁。

在自己電腦上預覽：在專案資料夾執行 `python3 -m http.server 8000 --directory site`，
然後用瀏覽器打開 `http://localhost:8000`。

## 語言與公開範圍

- **語言**：中文和英文兩個版本。
  機組名稱、能源類型、狀態、備註都需要英文對照（機組的英文名稱要另外建立對照）。
- **公開範圍**：第一版完全公開，不需要登入。
  日後如果要在網站上提供其他服務，才可能改成需要登入。
