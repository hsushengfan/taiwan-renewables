## 2. 已定案的設計決定（請照做，不要改）

- **電價走勢頁的主圖畫三條線**：表燈非營業（住宅）、表燈營業（小商家）、電力（產業），從 2002 年起。
- **再加一條「每度售電成本」線**，有幾年資料就畫幾年（2017 年起）。
- **含稅／未稅全站可切換**：
  - 資料庫一律存**未稅**值。
  - 顯示含稅時在前端乘 1.05。
  - 電價走勢頁預設**含稅**；轉供費率頁與之後的綠電比較、試算器預設**未稅**。
  - 切換的選擇要記住（同一位訪客跨頁一致）。
  - 圖表標題或圖例旁永遠標明目前是「含稅」或「未稅」。
- **調價時間軸**涵蓋 2015 年至今。
- 每張圖、每張表下方都要有「資料來源」連結與「資料更新至」日期。
- **中英文都要做**：頁面標題、圖例、說明文字、調價重點（`summary`）都要有英文版。資料表裡給人看的文字欄位請拆成 `_zh`、`_en` 兩欄（比照 `categories.name_zh`／`name_en`），英文請你翻譯，翻好後列給我確認。
- **每張圖表和表格都要能下載 CSV**（CLAUDE.md 的規則）。如果網站的下載功能還沒做，請先問我：是這次一起做一個共用的下載按鈕，還是等 12 月中那一批一起做。
- 這幾頁不需要時間範圍按鈕（24 小時／7 天），比照關於頁把 `#filters` 隱藏；也不需要每 3 分鐘自動更新。
- 所有數字顯示到小數第 4 位（元/度），112 年售電成本只有 2 位，照原精度顯示，不要補零。

## 3. 資料表設計（建議，可依現有慣例調整命名）

```sql
-- 010_electricity_price.sql

-- 年度平均單價（實績 = 電費收入 ÷ 售電度數），未稅
create table avg_unit_prices (
  year int not null,              -- 西元年
  category text not null,         -- 'lamp_residential' 表燈非營業 | 'lamp_business' 表燈營業
                                  -- | 'lamp_total' 電燈 | 'power' 電力 | 'total' 合計
  price numeric(8,4) not null,    -- 元/度，未稅
  primary key (year, category)
);

-- 每度售電成本
create table unit_costs (
  year int primary key,
  cost numeric(8,4) not null,       -- 每度售電成本，元/度
  avg_price numeric(8,4),           -- 同一來源的每度平均電價，可為 null
  period_note text,                 -- 例如 '1–9 月，未經審定'
  source text not null
);

-- 電價調整事件（含「不調整」）
create table price_adjustments (
  id serial primary key,
  effective_date date not null,     -- 生效日；不調整者填該次審議對應的 4/1 或 10/1
  decision text not null,           -- 'increase' | 'decrease' | 'freeze' | 'deferred'
  change_pct numeric(6,2),          -- 平均調幅 %，不調為 0，僅調產業者填產業調幅並在 note 說明
  avg_price_after numeric(8,4),     -- 調整後平均電價，元/度，未稅
  summary_zh text not null,         -- 一句話重點（中文，見 4.3）
  summary_en text not null,         -- 英文版，請翻譯後給我確認
  announcement_url text             -- 台電公告頁（內含該次電價表 PDF）
);

-- 轉供（輸配電業各項）費率，未稅
create table wheeling_rates (
  year int not null,                -- 適用年度（西元）
  fuel_type text not null,          -- 'average' 平均費率 | 're_zero_carbon' 再生能源(不排碳)
  ancillary numeric(8,4),           -- 輔助服務
  dispatch numeric(8,4),            -- 電力調度
  transmission numeric(8,4),        -- 轉供輸電
  distribution numeric(8,4),        -- 轉供配電
  total numeric(8,4),               -- 四項合計
  is_derived boolean not null default false,  -- true = 由含稅值 ÷ 1.05 換算
  source text not null,
  primary key (year, fuel_type)
);

-- 應有單價：台電依電價公式算出、電價「應該要有」的水準（每次審議提報一次）
create table required_unit_prices (
  meeting_date date primary key,    -- 審議會日期
  period_label text not null,       -- 例如 '114 年下半年'
  required_price numeric(8,4) not null,  -- 應有單價，元/度，未稅
  base_price numeric(8,4),          -- 簡報同頁載明的基準（現行）電價，沒寫就 null
  source_url text not null          -- 該場審議會的會議資料頁
);
```

**讀取權限照現有做法**（見 `005_website_api.sql` 與 `docs/database.md` 第 7 節）：五張表都 `enable row level security`，不要給 anon 任何 policy；另外寫 `security definer` 的 `api_` 函式給網站呼叫，並 `grant execute … to anon, authenticated, service_role`。建議兩個函式就夠：

- `api_price()`：一次回傳電價走勢頁需要的全部資料（平均單價、售電成本、調價時間軸、應有單價）。
- `api_wheeling()`：回傳轉供費率。

資料量很小（總共不到 200 列），不需要分頁或參數。`api.js` 加對應的 `getPrice()`、`getWheeling()`。

## 5. 頁面規格

### 5.1 電價走勢頁（階段 B）

- 主圖：折線圖，x 軸 2002–2025，y 軸元/度。四條線：表燈非營業、表燈營業、電力、每度售電成本（2017 起）。售電成本線用不同線型（例如虛線）與其他三條區分。
- 圖下方：調價時間軸。每次調整一個標記（漲、降、不調用不同顏色與圖示，不能只靠顏色區分），點開顯示日期、調幅、調整後平均電價、重點、台電公告連結。
- 含稅／未稅切換鈕，預設含稅。**售電成本線不隨切換變動**（成本沒有含稅的概念），切到含稅時在圖例註明「售電成本為未稅」。
- 文字說明要包含這三點：
  1. 「電燈」不等於住宅，包含小商家；「電力」主要是產業用電。
  2. 這是平均單價（實績），不是電價表上的牌價；個別用戶實付價格會因時間電價、契約容量、功率因數而不同。
  3. 2023 年起產業用電平均單價超過民生用電。

### 5.2 轉供費率頁（階段 C）

- 圖一：堆疊長條圖，2018–2026 年平均費率四項組成，長條頂端標合計。
- 圖二：折線圖，平均費率合計 vs 再生能源（不排碳）合計，凸顯不排碳費率從 2022 年 0.0524 升到 2026 年 0.3052。
- 表格：兩種費率的完整數字，換算值（is_derived）加註記。
- 含稅／未稅切換，預設未稅。
- 文字說明：四項費用各是什麼、誰要付哪幾項（見 4.4 說明）、費率每年 12 月前後由審議會核定並適用隔年整年。

## 9. 實作時確認的決定（2026-11-16）

開始實作前和使用者確認過，和上面的規格不同或補充的地方以這裡為準：

1. **CSV 下載**：這次一起做一個共用的下載按鈕（階段 B 開始），之後總覽、能源類型、機組頁也用同一個。
2. **原始精度**：`unit_costs` 加 `decimals` 欄位（預設 4，2023 年為 2），`cost`、`avg_price` 改用不限小數位數的 `numeric`，網站照 `decimals` 顯示、不補零。
3. **空白的重點**：`summary_zh`／`summary_en` 允許空字串，網站改顯示「不調整」或調幅。
4. **只調產業的說明**：寫在 `summary`，不另外加 `note` 欄位。
5. **主圖 x 軸**：延伸到 2026 年，只有售電成本有 2026 年的空心點（1–9 月）。
6. **含稅切換的記憶**：訪客沒選過時，各頁用各自的預設值；選過之後記住，所有頁面都照這個選擇。
7. **跟著含稅切換的數字**：調價時間軸的調整後平均電價、應有單價都會切換；只有每度售電成本不切換。
8. **主圖只畫三條線**（表燈非營業、表燈營業、電力）加售電成本；「電燈」和「合計」只存在資料庫，留給 CSV 下載和之後的試算器。
9. **資料表的文字欄位**：除了 `summary`，`unit_costs` 的備註與來源、`wheeling_rates` 的來源、`required_unit_prices` 的期間也拆成 `_zh`／`_en`；`unit_costs`、`wheeling_rates` 另加 `source_url`。
10. **price_adjustments**：`effective_date` 設為不可重複，讓重複執行時可以用它更新同一列。
